Description=Append disk usage to log
Documentation=man:df(1)
After=local-fs.target

[Service]
Type=oneshot
User=reports
ExecStart=/usr/local/bin/disk-report.sh
StandardOutput=append:/var/log/disk-report.log
StandardError=append:/var/log/disk-report.log

[Unit]
Description=Run disk-report daily
Documentation=systemd.time(7)

[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target

3.
Using StandardOutput=append:/var/log/disk-report.log is better than changing file ownership with chown because systemd opens and appends to the log file as root before dropping privileges to the unprivileged reports user.
 This maintains system security by keeping ownership of /var/log/disk-report.log with root, preventing the reports account from requiring direct write or modify permissions over system log files.

6.
We locked down the reports account to only run background tasks by --no-create-home and --shell /usr/sbin/nologin,
instead of acting like a real user.
 Without those settings, an attacker could hack the account and log straight into a terminal command line with a home folder to store their malicious files.
